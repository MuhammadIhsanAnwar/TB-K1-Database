# Lapak Gaming - Setup & Deployment Guide

## 🎯 Quick Facts

- **Framework**: Laravel 11
- **Frontend Build Tool**: Vite v8
- **CSS**: Tailwind CSS v4 (via @tailwindcss/vite)
- **Production Assets**: Stored in `public/build/` (generated by `npm run build`)
- **No Server-Side Build Needed**: Upload built assets, no `npm run dev` in production

---

## 🚀 Local Development (Windows/macOS/Linux)

### Prerequisites
- PHP 8.2+
- Composer
- Node.js 18+
- npm

### Setup

```bash
# 1. Install PHP dependencies
composer install

# 2. Install Node dependencies
npm install

# 3. Copy environment file
copy .env.example .env
# Or use your existing .env with local credentials

# 4. Generate APP_KEY
php artisan key:generate

# 5. Run migrations (if needed)
php artisan migrate

# 6. Start development server (Terminal 1)
php artisan serve
# Output: Server running at http://127.0.0.1:8000

# 7. Start Vite dev server (Terminal 2)
npm run dev
# Output: VITE will load CSS/JS on-demand
```

Visit `http://127.0.0.1:8000` in your browser.

**What Vite does in development:**
- Hot reload CSS/JS when you save files
- Tailwind CSS auto-compiles
- Lightning-fast development experience

## 📦 Production Build (Before Uploading to Server)

**IMPORTANT**: You MUST build assets locally before uploading to cPanel!

### Steps on Your Local Machine

```bash
# 1. Build production assets
npm run build
# This creates: public/build/manifest.json, public/build/assets/app.*.css, etc.

# 2. Install production PHP dependencies (no dev packages)
composer install --no-dev --optimize-autoloader

# 3. Ensure .env is production-ready:
#    - APP_ENV=production
#    - APP_DEBUG=false
#    - Correct database credentials
#    - APP_URL=https://lapakgaming.neoverse.my.id

# 4. Upload to cPanel via SFTP/FTP
#    Upload all files including public/build/ folder
```

### What Gets Built

After `npm run build`:
```
public/build/
├── manifest.json          (Vite manifest for Laravel)
├── assets/
│   ├── app.*.css         (Compiled & minified Tailwind CSS)
│   ├── app.*.js          (Compiled JavaScript)
│   └── ...
```

These CSS/JS files are:
- ✅ Minified
- ✅ Tree-shaken (unused CSS removed)
- ✅ Properly hashed for caching
- ✅ Production-optimized


### How Tailwind CSS Works in Production

**On Local (Development):**
```
User visits http://localhost:8000
    ↓
Laravel sees @vite directive
    ↓
Vite dev server running on http://localhost:5173
    ↓
Vite compiles resources/css/app.css (Tailwind) on-demand
    ↓
HTML includes: <link rel="stylesheet" href="http://localhost:5173/resources/css/app.css">
```

**On Hosting (Production - WITHOUT npm run dev):**
```
User visits https://lapakgaming.neoverse.my.id
    ↓
Laravel sees @vite directive
    ↓
Laravel finds public/build/manifest.json
    ↓
Laravel loads pre-built CSS: public/build/assets/app.*.css
    ↓
HTML includes: <link rel="stylesheet" href="/build/assets/app.*.css">
    ✅ NO Vite server needed!
    ✅ NO npm run dev needed!
    ✅ Fast static CSS/JS files
```

## ⚡ Performance Tips

### Tailwind CSS Specifics
- Only used classes are included in production CSS
- `resources/css/app.css` uses `@source` directives to scan:
  - `vendor/laravel` (pagination)
  - `resources/**/*.blade.php` (templates)
  - `resources/**/*.js` (JavaScript)

### Caching
- Static assets in `public/build/` are served with long cache headers
- Browser caches CSS/JS for days
- If you deploy new version, filenames change (hash), so cache invalidation is automatic

### Production Checklist
- [ ] `npm run build` completed locally
- [ ] `public/build/` folder uploaded
- [ ] `.env` has `APP_ENV=production`
- [ ] `.env` has `APP_DEBUG=false`
- [ ] Storage/bootstrap permissions set
- [ ] Database credentials correct
- [ ] Website opens without 500 error
- [ ] Tailwind CSS styling visible
- [ ] Forms/buttons functional

## 🆘 Troubleshooting

### "Tailwind CSS not loading" (Unstyled page)
- [ ] Check: `public/build/manifest.json` exists?
- [ ] Check DevTools Network tab: Is `/build/assets/app.*.css` returning 200?
- [ ] Run `npm run build` again locally and re-upload `public/build/`

### "500 Internal Server Error"
- [ ] Enable `APP_DEBUG=true` in `.env`
- [ ] Check `storage/logs/laravel.log`
- [ ] Verify database connection in `.env`
- [ ] Verify `storage/` and `bootstrap/cache/` permissions

### "App key missing"
- [ ] Ensure `.env` has `APP_KEY=base64:...`
- [ ] Or run locally: `php artisan key:generate --show` and copy to `.env`

### "Database connection failed"
- [ ] Verify `DB_HOST`, `DB_USERNAME`, `DB_PASSWORD` in `.env`
- [ ] Via cPanel: Create database and user in MySQL Databases
- [ ] Test locally that `.env` credentials work

## 📚 File Locations

| Path | Purpose |
|------|---------|
| `resources/css/app.css` | Main Tailwind CSS file (never edit directly - compiled by Vite) |
| `resources/js/app.js` | Main JavaScript entry |
| `resources/views/layouts/app.blade.php` | Main layout with `@vite` directive |
| `public/build/` | Built CSS/JS (created by `npm run build`, upload to server) |
| `package.json` | npm build scripts and dependencies |
| `vite.config.js` | Vite + Tailwind configuration |
| `.env` | Environment variables (NEVER commit, set locally) |
| `storage/logs/` | Error logs |

## 🚫 What NOT to Do

❌ Don't run `npm run dev` on production server
❌ Don't upload `node_modules/` folder (upload `vendor/` instead)
❌ Don't commit `.env` to Git
❌ Don't leave `APP_DEBUG=true` in production
❌ Don't run `composer install` without `--no-dev` flag on production

## 💡 Key Concepts

**Vite = Frontend Build Tool**
- Bundles CSS/JS locally
- Creates `public/build/` with production-optimized files
- On server: Laravel loads from `public/build/` (no build process needed)

**Tailwind CSS = CSS Framework**
- Utility-first CSS classes
- Only includes CSS for classes you actually use (tree-shaking)
- Works seamlessly with Vite via `@tailwindcss/vite` plugin

**Laravel @vite Directive**
- In development: Points to Vite dev server
- In production: Points to built files in `public/build/`
- Automatic switching based on `.env` (APP_ENV)
